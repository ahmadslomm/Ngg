## 3. What was built

### `src/queue/index.ts` — Queue Registry
- **Queue factory** `getQueue(name)` — lazily creates & memoizes one BullMQ `Queue` per name.
- **Canonical names** `QUEUE = { notifications, ranking, wallet, gifts, vip, decorations, rooms, moderation, reconcile }` — **namespaces only; declaring a name wires no job.**
- **Retry/backoff defaults** `defaultJobOptions` — `attempts: 3`, exponential backoff (1s/2s/4s), `removeOnComplete {count:1000, age:24h}`, `removeOnFail {count:5000}`.
- **Job naming convention** `jobName(queue, action)` → `"<queue>:<action>"` (e.g. `gifts:pool-settle`).
- **Producer** `enqueue(queue, action, data, opts?)`.
- **Graceful shutdown** `closeQueues()` — closes every memoized queue (each closes its own BullMQ-owned connection).

### `src/workers/index.ts` — Worker skeleton
- **Worker factory** `createWorker(name, processor, opts?)` — builds a `Worker` with the shared connection descriptor, default concurrency (5), and `completed`/`failed`/`error` handlers wired to a small structured logger.
- **Empty processor registry** + `registerWorker(def)` — future job-owning tasks push handlers here; **none registered now**.
- **`bootstrap()`** — starts a worker per registered processor; logs `no_workers_registered` when empty (valid skeleton run).
- **`shutdown(signal?)`** — drains workers (`worker.close()`), `closeQueues()`, disconnects Redis clients. Wired to `SIGTERM`/`SIGINT` in `main()`.
- **Guarded entrypoint** — `main()` runs only when the file is executed directly (`worker` script), never when imported by tests.

### Redis reuse — the one non-obvious decision
BullMQ **bundles its own copy of ioredis**, so passing the app's `redis` instance (or its typed `RedisOptions`) as a `connection` fails to type-check across the two ioredis copies (this actually broke the first build — see §5). Resolution: derive plain BullMQ **`ConnectionOptions`** (`host/port/username/password/db` + `maxRetriesPerRequest: null`) from the same `redis.options` the `lib/redis.ts` singleton already uses. This still **"uses the existing Redis"** (same server/URL/auth from `redis.ts`) while letting BullMQ construct and **own** its connections, so `queue.close()`/`worker.close()` clean up with no leaked handles. `maxRetriesPerRequest: null` is mandatory for BullMQ and is intentionally incompatible with the request-path singleton (`3`, fail-fast) — a second reason not to share the instance.

## 5. Issues encountered & resolved

### (a) Build error — cross-package ioredis type clash 🔧 fixed
First `npm run build` failed: passing the app-ioredis `Redis` instance/options to BullMQ (which bundles a different ioredis) produced an incompatible-`options` type error. **Fixed** by switching to plain `ConnectionOptions` derived from `redis.options` (§3). Rebuild → exit 0.

### (b) Pre-existing flaky test surfaced (NOT caused by T1.3) 🔎 root-caused & remediated
After the build fix, the suite showed **1 failure in `discovery.api.test.ts`** — a test my additive files cannot influence (it reproduced in **isolation**, and `queue.test.ts` itself passed 7/7).

**Root cause:** the persistent `voxa` test DB had accumulated **472 rooms (449 live)** from my repeated `npm test` runs across T1.1–T1.3. Discovery pages `take:20` ordered by `onlineCount desc, id desc`; the test's freshly-created `online:5` room was crowded off page 1, so `find()` returned `undefined`. The discovery test never cleans up its rooms — a pre-existing **test-isolation weakness**, merely surfaced by cumulative runs.

**Remediation (test-environment hygiene, not a code/schema change):**
1. `prisma migrate reset --force` — cleared accumulated fixtures and **re-applied the existing 7 migrations** (authored no new migration). Room count → 0; discovery went green.
2. That exposed 5 `medals` tests that depend on **seeded medals** — Prisma auto-seed isn't configured (`prisma.seed` undefined), so reset didn't seed. Ran `npm run seed` ("seed complete").
3. Full suite re-run → **233/233 green**.

This remediation touched **no source file and authored no migration**; it only restored the test DB to the clean state tests assume.
