> Executed **T3.1** exactly as the approved design. Added a **read-only** nightly `reconcile:wallet` worker that recomputes each wallet's balance from the append-only `WalletLedger` and diffs it against `Wallet.*`, alerting on drift. It **NEVER writes** — no `Wallet` mutation, no `WalletLedger` row, no auto-heal, no audit row, no migration. Two new files only (`wallet-reconcile.ts` + test); **no money path, infra, or schema file touched**; the worker is **NOT wired into boot**. ## 4. Implementation

### 4.1 Reconcile flow (`runWalletReconcile(opts?)`)
1. **Page** wallets by a `userId` cursor (`orderBy userId asc`, `take batchSize`, default 1000) — or a single scoped page when `opts.userIds` is given.
2. Per page: **one** `walletLedger.groupBy({ by:['userId','currency'], where:{ userId:{ in: pageIds } }, _sum:{ delta } })` — the recomputed balance per (user, currency).
3. Compare each **reconcilable** column to its ledger sum; collect **candidate** userIds (deduped).
4. **Re-verify** each candidate once (`reVerifyUser`: fresh `wallet.findUnique` + fresh per-user `groupBy`) — a transient read-skew from a concurrent money tx resolves to 0 here and is dropped; a genuine drift persists.
5. Record confirmed drifts + `log('error', 'wallet_drift', …)`. Return `{ scanned, drift: [{ userId, currency, col, wallet, ledger, diff }], ok }`.

### 4.2 Recompute from `WalletLedger`
The recomputed balance for currency `c`, user `u` = `Σ delta` over that user's ledger rows for `c`. On the clean path this is **one aggregate per page** — no per-user query. The per-user aggregate (`ledgerSums`) runs **only** for the rare flagged candidates during re-verify, so the common (all-clean) path stays at one query per page.

### 4.3 Comparing `Wallet.*` — columns in / out
| Column | In compare? | Why |
|---|---|---|
| `coins` (cur 0) | ✅ | fully ledger-backed |
| `beans` (cur 1) | ✅ | fully ledger-backed |
| `vipCoins` (cur 2) | ✅ | ledger currency exists (0 today; 0==0 reconciles) |
| `balance` (cur 3) | ✅ | ledger currency exists (0 today; 0==0 reconciles) |
| `coinsTotal` | ❌ | lifetime-grant counter (incremented on recharge only) — NOT a net-ledger balance |
| `version` | ❌ | optimistic lock, not money |

`diff = wallet[col] − ledgerSum(currency)`; any non-zero diff (after re-verify) is drift.

### 4.4 Recording drift
Each confirmed `(user, currency)` → a `DriftEntry { userId, currency, col, wallet, ledger, diff }` in the returned report. **No DB write.**

### 4.5 Alerting
- **Structured error log** per confirmed drift (`mod:'reconcile', msg:'wallet_drift', userId, col, wallet, ledger, diff`) — mirrors the worker logger; silent under `NODE_ENV=test`, honors `LOG_LEVEL`. A log/alert rule keys off `wallet_drift`.
- **Returned report** (`{ scanned, drift, ok }`) — the assertable surface (the test checks this, not fragile stdout capture).

### 4.6 Idempotency & safety
- **Pure read ⇒ inherently idempotent**: repeated runs yield the same report, zero state change.
- **False-positive guard**: the re-verify step (fresh wallet + ledger read for a flagged user) drops a drift that was only a read-skew across the batch reads. The "≥7 days green" gate further filters transient noise.
- No transaction, no lock, **no money mutation**.

### 4.7 Worker plumbing (exposed, NOT wired to boot)
- `walletReconcileProcessor(job)` — runs the sweep for `reconcile:wallet`, ignores other `reconcile`-queue jobs.
- `registerWalletReconcileWorker()` (`registerWorker` on `QUEUE.reconcile`) + `scheduleWalletReconcile(everyMs = 86_400_000)` (nightly repeatable) — **defined but NOT called from `workers/index.ts` main** (the T2.2/T2.4/T2.7/T2.8 deferral). So the job does not run in production until a later boot-wiring step.

## 6. Tests added (`wallet-reconcile.test.ts`, 8 — worker, real DB + BullMQ)

1. **clean** — a seeded (opening ledger) + properly-ledgered-debit wallet → zero drift, `ok:true`; wallet unchanged (read-only).
2. **injected drift (coins)** — wallet coins +999 with no ledger row → detected (`wallet 1999 / ledger 1000 / diff 999`); wallet **not** auto-healed (still 1999).
3. **multi-currency** — coins +5 & beans −3 without ledger → both flagged with correct signed diffs.
4. **excluded columns** — coinsTotal +9999 & version +7 → **no** drift (`ok:true`).
5. **isolation within a scan** — a clean user beside a drifted one → only the drifted is flagged (exercises re-verify + compare).
6. **full cursor-paged scan** — no `userIds`, `batchSize:500` → the injected drift is found (exercises the cursor loop).
7. **processor** — a foreign job name is a no-op; `reconcile:wallet` returns a report.
8. **schedule** — `scheduleWalletReconcile` creates a removable repeatable on the `reconcile` queue.

*Isolation:* fresh users per test; scoped runs pass `userIds` so the check sees only this test's wallets (the shared DB's other wallets don't affect the per-user assertions). **Verified stable across two runs (8/8).**
