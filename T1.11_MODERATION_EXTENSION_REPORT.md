## 1. Why this change

T1.11 wired the `RoomMember.permissions` bitmap into `requireRoomAdmin` and gated `setSeatLock` (LOCK_SEAT) and `kick` (KICK). Two room-moderation actions were still on **role-only** checks and never consulted the bitmap:
- **Host mute** (`/rooms/:id/seats/:pos/mute`) — enforced staff via the FSM's role check only.
- **Room ban/unban** (`/rooms/:id/ban`) — enforced via a local `assertRoomStaff` that checked `role >= Admin` only (owner OR admin), ignoring the permission bitmap.

This extension finishes that plumbing so a room admin's fine-grained bitmap actually governs mute and ban — the "permission enforcement completion" you scoped. Existing behavior is preserved: with `permissions = 0` (every current member) the guard falls back to role, so nothing changes for today's rooms.

## 4. Flow: route → authz → service

**Ban/unban (enforced at the route boundary, before the service):**
```
POST /rooms/:id/ban
  → app.authenticate (req.user)                     [unchanged]
  → assertRoomPermission(roomId, uid, KICK)          [moderation.routes]
        loads Room.ownerId + RoomMember{role,permissions}
        → requireRoomAdmin({role, permissions}, KICK) [lib/authz.ts]
              Owner → pass · Admin+non-zero-mask missing KICK → throw insufficient_permission
              Admin+0/undefined mask → role fallback (pass) · Listener → throw insufficient_role
  → (only if authorized) moderationService.banFromRoom(...)   ← mutation
  catch(AppError) → replyError → 403                 [no Ban row written on denial]
```

**Host mute (enforced in the service, composing with the ServiceResult flow):**
```
POST /rooms/:id/seats/:pos/mute
  → app.authenticate
  → room.service.setMute(roomId, actor, pos, muted)
        load state; seat = seats[pos]
        isHostMute = seat.userId && seat.userId !== actor
        if isHostMute:
           requirePermission(roomId, actor, MUTE)      [→ repo.getMembership → requireRoomAdmin]
             denied → return { ok:false, error } BEFORE persist/emit   ← no mutation, no WS
        apply FSM setMute → persist seats → emit mic.update
```
The service converts the guard's throw into a `ServiceResult` error code (so it never rejects into a fire-and-forget route); the route's existing `fail()` maps `insufficient_permission`/`insufficient_role` → 403 (mapping added in T1.11).
