## 3. Schema / migration

```prisma
model UserGiftBag {
  id        BigInt   @id @default(autoincrement())
  userId    BigInt
  giftId    BigInt
  qty       Int      @default(0)
  expiresAt DateTime?           // null = permanent; a past value excludes the row from the merge
  updatedAt DateTime @updatedAt
  user      User @relation(fields: [userId], references: [id])
  gift      Gift @relation(fields: [giftId], references: [id])
  @@unique([userId, giftId])
  @@index([userId])
}
// User: + giftBag UserGiftBag[]   ·   Gift: + bagEntries UserGiftBag[]
```

## 4. UserGiftBag design

One row per `(userId, giftId)` (enforced by the unique index) holding a `qty` and an optional `expiresAt`. It models the "backpack" gift source — free/awarded gifts a user can later send. A row **counts toward the catalog** only when it is **live**: `qty > 0` **and** (`expiresAt` is null **or** in the future). Expired grants are simply not counted (no sweep needed for the read path). This task is **read-only plumbing**; the write side (grant on receipt, decrement on send) belongs to later tasks (send = T1.15).

## 5. API / read flow

`GET /gifts` (public, unchanged envelope `{ code, message, data: { items } }`):
```
GET /gifts[?category=]
  → best-effort optional auth:  try req.jwtVerify() → userId (skip refresh tokens); on failure → anonymous
  → listGiftCatalogue({ category?, userId? })
        gifts = Gift.findMany({ enabled, category? } order by category,sort)
        if userId: bag = UserGiftBag.findMany({ userId, giftId in gifts, qty>0, expiresAt null|future })
                   qtyByGift = map(giftId → qty)
        items = gifts.map(g → { …existing gift fields…, bag_qty: qtyByGift[g.id] ?? 0 })
  → { code:0, message:'ok', data:{ items } }
```
Each item preserves **every existing field verbatim** (`id, name, category, price_coins, icon_url, anim_url, anim_type, combo_enabled`) and **only adds `bag_qty`**. The optional auth never blocks the public catalog: an anonymous request (or a request in an app without JWT registered) yields `bag_qty: 0` for all gifts.

## 6. Relations with User / Gift

- `UserGiftBag.user → User` (FK `userId`), back-relation `User.giftBag[]`.
- `UserGiftBag.gift → Gift` (FK `giftId`), back-relation `Gift.bagEntries[]`.
- `@@unique([userId, giftId])` guarantees at most one bag row per user per gift (so `qty` is authoritative); `@@index([userId])` supports the per-user merge lookup. The merge query filters by `giftId IN (catalog ids)` so it never scans the whole bag.
