## 3. What was built & design decisions

### `wornDecorations(userId)` — worn-decoration aggregation, empty until T1.13
```ts
private async wornDecorations(_userId: bigint): Promise<Array<{ slot: string; url: string }>> {
  return [];
}
```
Included alongside `medals` in the card's `Promise.all` for both `getProfile` (public `/users/{id}`) and `getMyProfile` (`/users/me`). The card now carries `decorations: []`.

**Design decisions:**
1. **Empty array, not a fabricated join.** The authoritative store is `UserDecoration`, which does not exist yet (arrives in T1.13, no migration in T1.7). The spec explicitly says "Decoration/medal joins tolerate empty until T1.13", so the honest implementation is an empty aggregation now. The card's already-present cached fields (`avatar_frame_url`, `vip_frame_url`, `vip_entry_effect_url`) still carry the currently-worn frame/effect, so no data is lost — `decorations` is the explicit contract-§6 slot that T1.13 fills.
2. **Kept `async` with the `userId` parameter.** The signature is the final one; T1.13 swaps only the body for a `UserDecoration` query — callers and card shape don't change. This avoids a churny signature change later.
3. **Added to both card builders,** not just `getProfile`. `/users/me` and `/users/{id}` render the same card; giving them a divergent shape (one with `decorations`, one without) would be worse for clients. This is card-shape consistency, not scope creep — both are "the profile card" named by the goal.
4. **Did NOT modify `users.routes.ts`.** Every route T1.7 needs already exists (`GET /users/:id`, `POST|DELETE /users/:id/follow` in users; `POST|DELETE /users/:id/block` in moderation). Per the established principle (don't edit a file just to match the plan's glob — same as not creating `auth.service.ts` in T1.5), I left it untouched. The card enrichment is a pure service-layer change.
5. **Did NOT add block code.** `moderationService.blockUser` + routes + the `follow()` block-edge refusal already implement "block prevents interaction". T1.7 only needed to confirm and test it.
