**Design decisions (grounded, documented for review):**
1. **Platform-admin gate = `AdminUser.role >= 2`.** `authenticateAdmin` carries only the admin **id** (not role — verified in `server.ts` and the test shim), so the role is looked up from `AdminUser` inside the service. Role 2 is the seed/top admin (`prisma/seed.ts` creates root at role 2; `makeAdmin` defaults to 2). This keeps the check **in-module** — no `server.ts`/`harness.ts` change. A lower/disabled admin → `403 forbidden`.
2. **Cache-bust = a Redis version stamp** (`cfg:ver:<namespace>`, `INCR` on publish). Catalog reads currently hit Prisma directly (no populated cache to delete), so a monotonic version stamp is the race-free "something changed" invalidation signal readers compare against. Lives in the **config module** (`~config/*`), the natural home for the readers.
3. **Catalog scope = the five missing editors** (Product, DecorationItem, GiftCategory, RoomTheme, LevelConfig). Gift/VipLevel/Banner/Announcement already have editors in the pre-existing `admin.service.ts`; I did **not** rewrite those (avoids regressing the existing admin suite) — see §8 risk 1.
4. **Mutations gated; lists open to any admin** (mirrors the existing admin routes; the test line gates "each **mutation**"). **Delete = soft-disable** (`enabled=false`) for catalogs with an `enabled` column; **hard delete** for `LevelConfig` (it has no `enabled`).

## 4. Implementation

**Cache seam (`config/catalog-cache.ts`):** one namespace per editable catalog; `bustCatalog(ns)` = `redis.incr('cfg:ver:'+ns)` → the new version; `catalogVersion(ns)` reads it (0 when never edited). Forward-looking: reads don't consult it yet, but every publish now stamps a bump — the invalidation signal T2.9 requires and the test asserts.

**Service (`admin/catalog-admin.service.ts`):**
- `requirePlatformAdmin(adminId)` — `AdminUser` role lookup; `role >= 2` (`PLATFORM_ADMIN_ROLE`) & enabled, else `AppError('forbidden', 403)`.
- `auditWrite(adminId, action, targetType, targetId, before, after, ns)` — writes the `AuditLog` row (before/after serialized; a null side → `Prisma.JsonNull`) **and** `bustCatalog(ns)`.
- Per catalog: `list*` (open), `create*` / `update*` / `remove*` — each mutation calls `requirePlatformAdmin`, captures **before** (fetched pre-mutation; 404 if missing on update/delete), mutates, then `auditWrite(before, after)`. Update/delete on a missing row → `not_found` (404).

**Routes (`admin/admin.routes.ts`, additive):** `GET/POST/PATCH/DELETE` under `/admin/{products,decorations,gift-categories,room-themes,level-configs}`, each `authenticateAdmin`-guarded at the route and platform-admin-gated in the service; zod-validated bodies; snake_case ⇄ camelCase mapping; `replyError` maps `AppError` (403/404). Explicit-Int-id catalogs (gift-category/room-theme) take `id` in the create body; BigInt-id catalogs (product/decoration) autoincrement.

## 5. Platform-admin gating & audit (the T2.9 contract)

- **Platform-admin-only:** a `role < 2` admin hitting any catalog **mutation** gets **403 `forbidden`**; `role >= 2` succeeds. Lists remain open to any authenticated admin. Unauthenticated → 401 (existing `authenticateAdmin`).
- **before/after AuditLog:** every create writes `before:null, after:<row>`; every update writes the real `before` + `after` (distinct values); every delete writes `before:<row>, after:<disabled row>` (soft) or `after:null` (LevelConfig hard delete). `actorAdminId` = the acting admin.
- **cache-bust:** each publish bumps `cfg:ver:<namespace>`; the test asserts the version increments per publish.
