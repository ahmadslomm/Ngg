## 4. Implementation

### 4.1 Purchase transaction (one serializable tx)
```
purchase(userId, level, { source?, orderId?, idempotencyKey? })
  plan = VipLevel[level]  (404 if absent)
  serializableTx:
    0. idempotency: if idempotencyKey already in WalletLedger → throw idempotent_replay (409)
    1. wallet.upsert; require coins ≥ plan.priceCoins else insufficient_coins (400)
    2. debit: wallet.coins −= price ; WalletLedger{ coins, −price, reason:VipPurchase(6), refType:'vip', refId:level, idempotencyKey }
    3. VipHistory.create{ level, startedAt, expiresAt=computeExpiry(now, current?.expiresAt, durationDays), source, orderId }
    4. Profile cache: vipLevel = highest still-active level ; vipExpireAt = that tier's expiry
    5. grant decorations: for id in benefits.decorations → UserDecoration upsert (expiresAt = membership expiry; free)
    → { level, expiresAt, coinsAfter, historyId, grantedDecorations[] }
  (after commit) emitToUser(vip.purchased)  — best-effort; null gateway = no-op
```

### 4.2 Decoration grant (`grantVipDecorations`)
Perks, **not charged** — the only debit is the VIP price (step 2). For each configured `DecorationItem` id: skip if missing/disabled (config drift must not block a paid purchase); else create the `UserDecoration` row (not equipped) with `expiresAt = membership expiry`, or, if already owned, **extend without shortening** (a permanent/longer-lived row is preserved). Runs **inside** the purchase tx → grant + debit commit together (fail → neither).

### 4.3 Privilege resolver (`getMyPrivileges`)
Reads the highest still-active `VipHistory`; returns `{ level, active, name, privileges: benefits, badge_url, frame_url, entry_effect_url, expires_at }`, or the inert `{ level:0, active:false, privileges:{} }` when none.

## 6. Wallet / ledger integration

Uses the established **inline** money pattern — no ledger-architecture change:
- **Debit:** `tx.wallet.update` (coins − price) + `tx.walletLedger.create{ currency:Coins(0), delta:-price, balanceAfter, reason:VipPurchase(6), refType:'vip', refId:level, idempotencyKey }`.
- **Idempotency anchor:** the existing unique `WalletLedger.idempotencyKey` (same mechanism as gifts T1.15) — a same-key retry is caught before any debit.
- **Grant writes no ledger row** (decorations are free perks; no money moves). `lib/ledger.ts` **untouched** (`VipPurchase=6` already existed).
