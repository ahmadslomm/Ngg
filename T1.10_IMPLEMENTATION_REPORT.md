## 3. FSM — states, transitions, and the two additions

**Seat state:** `SeatState ∈ { Empty=0, Occupied=1, Locked=2 }`. **Mic flags (independent):** `micMuted` (self) and `micMutedByAdmin` (host). **RTC role** = broadcaster iff seated and not `micMutedByAdmin`.

### `inviteToSeat(state, actorId, targetId, position)` — NEW
Host/admin seats a **target** user (⇐ old `inviteJoinMic`). Authoritative seating, like `takeSeat`, but initiated by staff for someone else.
- **Guards:** actor must be staff (`not_allowed`); seat exists (`seat_not_found`); not locked (`seat_locked`); not occupied (`seat_taken`); target not already seated (`already_seated`).
- **Effect:** target → `Occupied`, mic flags reset.
- **Events:** `seat.update` (occupied — existing) **+** `seat.invited { position, userId, by }` (**additive, new**).

### `setSelfMute(state, actorId, position, muted)` — NEW
A **self-only** mic toggle, distinct from the "smart" `setMute`.
- **Guards:** seat exists/occupied (`seat_not_found`/`seat_empty`); actor **is** the occupant (`not_allowed` — cannot mute another); **not** force-muted (`admin_muted`).
- **Effect:** writes **`micMuted` only**; `micMutedByAdmin` is never touched → it **cannot lift a host force-mute**, and the two flags stay independent.
- **Event:** `mic.update { position, muted, byAdmin:false, canSpeak }` (existing event).

Existing transitions (take/leave/switch/lock/mute/role/kick) are unchanged in behavior; their event emissions were routed through the new `room.events` builders (byte-identical event names/payloads).

## 7. Design decisions

1. **Kept existing event names + 200 responses** (not "204 + seat.updated"). The current design already emits a seat/mic event per mutation; renaming would break `room.api.test.ts` (out of scope) and existing clients, violating "don't break rooms". Only the additive `seat.invited` was introduced.
2. **`room.events.ts` as a real registry** — event-name constants + payload builders, used by the whole seat FSM (existing emissions refactored to it with byte-identical output). Self-contained (no imports) so the dependency stays one-way: `seat-state → room.events`.
3. **`self-mute` as a dedicated transition**, not a reuse of the "smart" `setMute`. `setMute` decides self-vs-host by actor; a dedicated `setSelfMute` guarantees self-only semantics (`/self-mute` on someone else's seat is refused, not silently turned into a host-mute).
4. **`invite` seats the target directly** (staff authority), matching the contract's `Seat`-table effect; membership is not re-checked in the pure FSM (consistent with the other transitions — the service/route own membership).
5. **Minimal service surface** — the two new methods reuse the existing private `applySeat`, so persistence + broadcast plumbing is untouched.
