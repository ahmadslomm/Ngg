## 3. What was built

### `src/lib/events.ts` — the bus
- **`emit(event, payload, sinks?)`** — resolves one domain event to its destinations and dispatches each; resolves after all fanouts settle. Returns an `EmitResult { event, routed, targets[] }` for observability/tests.
- **`DomainEvent { room?, userId?, data? }`** — `room`/`userId` are the gateway routing addresses; `data` is the body forwarded verbatim to clients and jobs.
- **Central routing table `ROUTES`** — domain event → destinations. Three fanout kinds:
  - `room` → `emitRoomEvent(room, {ev, data})`
  - `user` → `emitToUser(userId, {ev, data})`
  - `queue` → `enqueue(queue, action, {event, room, userId(string), data})`
  - Multi-entry rows (`gift.sent`, `rank.update`) fan a single event out to **both** the gateway and a queue — the reason a bus exists over direct broadcast calls.
- **Injectable `EventSinks` (DI)** — same style as the gateway's `verifyToken`/`hooks`. Production binds the real `emitRoomEvent`/`emitToUser`/`enqueue`; tests inject fakes, so routing is asserted with **no live Redis/DB**.
- **Inference fallback** — an event absent from the table infers a single gateway target from the payload (`room` → room, else `userId` → user), so the bus is a safe drop-in during progressive adoption. **Inference never enqueues** — a queue fanout must be declared explicitly. Marked `routed: false` in the result.
- **Best-effort** — echoes the gateway's L1 policy: a throwing/failing sink is captured in `targets[].ok=false` with the error detail and **swallowed**, never rejected into a fire-and-forget caller. Missing address (a `room` fanout with no `payload.room`) is a recorded skip, not a throw.
- **BigInt safety** — `userId` is serialized to a string on the queue payload (BigInt is not JSON-serializable → BullMQ would throw).
- **Tiny structured logger** — silent under `NODE_ENV=test`, honors `LOG_LEVEL`; logs only the truly-undeliverable case (`event_undeliverable`).

### The one design decision — additive seam, not a rewrite
The gateway already exposes `emitRoomEvent`/`emitToUser`, and ~9 modules call them directly today. T1.4 does **not** rewire those (out of the spec's file list and would touch live features). Instead the bus **wraps** those primitives behind `emit()`, so future tasks can migrate call sites one at a time and opt into queue fanout where a background job is warranted. Until then the table is dormant: nothing calls `emit()` in the live path, so there is no runtime side effect and no messages land on the empty queues.

The 9 new cases:
- user-channel event → `emitUser` only (room/queue untouched).
- room event → `emitRoom` only.
- **multi-fanout** (`rank.update`) → both `emitRoom` **and** `enqueue('ranking','recompute',…)`; target order `['room','queue']`.
- **bigint → string** in the queue payload (`userId` = `'99'`).
- inference: unrouted event with a `room` → room broadcast, `routed:false`, **never enqueues**.
- inference: unrouted event with a `userId` → user broadcast, `routed:false`.
- orphan event (no route, nothing to infer) → dropped, `targets:[]`.
- **best-effort**: a throwing sink is recorded (`ok:false, detail:'redis down'`), `emit` does **not** reject.
- **missing address**: `room.joined` without a room → recorded skip (`ok:false, detail:'no-room'`), no broadcast.
