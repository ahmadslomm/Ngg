## 4. Wallet read flow

```
GET /wallet
  → app.authenticate (req.user.id)
  → walletService.getWallet(userId)
        prisma.wallet.upsert({ where:{userId}, update:{}, create:{userId} })   ← lazy-init only
  → serialize → { coins, coins_total, vip_coins, beans, balance }

GET /wallet/ledger?page&page_size[&currency&reason]
  → app.authenticate (req.user.id)
  → walletService.getLedger(userId, { page, pageSize, currency?, reason? })
        prisma.walletLedger.findMany({ where:{userId,…}, orderBy:{createdAt:'desc'}, skip, take })
        + count(where)
  → serialize → { items[newest-first], total, page, page_size }
```
Notes: `getWallet` uses `upsert` with `update:{}` — it **lazily creates a zero wallet** if none exists but **never modifies an existing balance and writes no ledger row** (compliant with "read-only; no balance change; no new transactions"). No write path is invoked by either endpoint.

## 5. Ledger architecture & the "single money writer" audit (honest finding)

`lib/ledger.ts` is the **shared money vocabulary**, not a writer:
```ts
export enum Currency { Coins=0, Beans=1, VipCoins=2, Balance=3 }
export enum LedgerReason { Recharge=0, GiftSend=1, GiftRecv=2, Exchange=3, Withdraw=4, AdminAdjust=5, VipPurchase=6, Commission=7, LuckyWin=8 }
```
It exposes **no write function**. Balance mutations are performed **inline in each economy service**, each pairing a `wallet.update` with a `walletLedger.create` carrying `balanceAfter`:
- `wallet.service.ts` (recharge grant, exchange, withdrawal)
- `gifts/gift.service.ts` (gift debit/credit, lucky win)
- `vip/vip.service.ts` (vip purchase)
- `admin/admin.service.ts` (admin adjust)

**So the goal "confirm `lib/ledger.ts` is the single money writer" cannot be truthfully confirmed — it is currently false.** What *is* true and testable is the **invariant**: every balance change is ledgered so that the wallet balance equals the latest `balanceAfter` for that currency (verified by the new test). Actual **centralization** of writes behind one ledger writer is **out of scope for T1.12** (read-only) and is explicitly the job of **T3.x — Wallet finalize** (per the task's own note). Per your constraints (no economy logic, no rebuild, read-only), I did **not** refactor; I report it as a finding (§8, risk 1).
