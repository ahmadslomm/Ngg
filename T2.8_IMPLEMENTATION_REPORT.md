## 4. Implementation — ranking aggregation

The existing `ranking.service` had Redis **live** scores (`addScore`) + a manual `snapshot()`. T2.8 adds the **durable, queue-driven** path:

- **`applyScore(board, subjectId, delta, at)`** — upsert-increments the `Ranking` row for the subject across **all four periods** (day/week/month/total). Distinct from the Redis board: this is the persisted "board period rows". `rank` is left **0** on create (a later snapshot/ranking pass computes ranks); we only move `score`, so the counter is durable and increments cleanly.
- **`aggregateGiftSend({ senderId, coins, recipients:[{id,charm}], at })`** — a gift send's board contributions: sender **coin-flow** on `Wealthy` + `Gift`, each recipient's **charm** on `Charm`. All across every period.
- **`enqueueGiftSend(...)`** — the producer: enqueues a `ranking:agg` job (`kind:'gift-send'`, BigInt→string). This is the queue seam a gift-send caller uses.

**`workers/jobs/ranking-agg.ts`** — the consumer: `rankingAggProcessor` handles `ranking:agg` jobs, dispatching `gift-send` → `aggregateGiftSend` and a generic `score` → `applyScore`; foreign job names / unknown kinds are no-ops. `registerRankingAggWorker()` is the T1.3 hook (not wired into boot — the T2.2/T2.4/T2.7 deferral).

## 5. Implementation — notifications

The `notifications` module was **empty**; built it out:

- **Producers** (enqueue a `notifications:deliver` job): `enqueueNotification(input)` (generic) and typed `notifyFollow(follower,target)` / `notifyRoomKick(user,room,by)` / `notifyVipExpired(user,level)` — one job each, with the right `kind`/`title`/`body`/`payload`.
- **`deliver(job)`** — the consumer action: creates the durable `Notification` row **and** best-effort `emitToUser(userId, { ev:'notification.new', … })`. Split producer/consumer so a request-path caller (follow/kick) never blocks on the DB write or socket push — it just enqueues; the worker persists + pushes.

**`workers/jobs/notify.ts`** — `notifyProcessor` handles `notifications:deliver` (skips a malformed/foreign job) → `deliver`. `registerNotifyWorker()` is the T1.3 hook (not wired into boot).
