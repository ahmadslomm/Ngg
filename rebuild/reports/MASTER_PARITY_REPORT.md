percentage against an unknown denominator would be fiction.

## The denominator problem

The single most important correction in this extraction: the original surface is
**397 endpoints**, not 280. Static APK analysis found 280;
live H5 capture found 124; they overlap on only 7. Every earlier
parity estimate in this project used the smaller number and was therefore **optimistic by about a
third**.

And of those 397, only **47** have a captured response
shape. So the true state is:

- **47 endpoints** we could faithfully rebuild today (contract known).
- **77 endpoints** whose name and parameters are known but whose response is not.
- **273 endpoints** known only as a name from static analysis.

The rebuild's 191 routes already exceed the 47 fully-specified
originals. **Further endpoint parity is capture-bound, not engineering-bound.**

## What cannot be recovered

1. **Gacha / lucky-draw probability tables** — server-side; absent from every capture. Blocks: luckyBags, MagicBox, LuckyDraw.
2. **Economy constants (gift→charm ratio, room-exp accrual, commission rates)** — never exposed by any captured response. Blocks: charm/wealth accrual, agency settlement.
3. **avatarFrameJson / carFrameJson descriptor shape** — field observed, contents never captured. Blocks: rich decoration descriptors.
4. **srcType → DecorationItem.kind codebook** — 3 observations from 1 user is not a codebook. Blocks: decoration import (kind left unset).
5. **Medal catalogue** — medal.getMedalList never captured; the captured medal endpoint returned an empty list. Blocks: Medal.iconUrl population.
6. **SVIP tiers/benefits** — Action/SVip.* returned error for the test account (not an SVIP). Blocks: SVIP subsystem.
7. **Agency hierarchy depth** — captured guild responses were empty for the test account. Blocks: Agency → Agents → Hosts modelling.
8. **Original ids and transaction history** — lives only in the operator's database. Blocks: nothing buildable — noted for completeness.
