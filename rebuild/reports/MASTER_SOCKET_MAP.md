## 3. Original realtime protocol

The original did **not** use Socket.IO. It used a binary IM protocol; **147 opcodes**
were recovered (`analysis/im_opcodes.json`).

**This is the single largest realtime unknown.** Our event vocabulary is a rebuild-owned design, not
a recovered one. Mapping 147 original opcodes onto 22 rebuilt
events has **not** been done and cannot be done from static evidence alone — it needs a capture of
the live IM socket, which no session has performed.

**Realtime parity is therefore UNKNOWN, not a percentage.** Any number here would be invented.

## 4. Missing mechanics

| Mechanic | Status |
|---|---|
| Heartbeat / ping-pong | Socket.IO built-in; the original's interval is UNKNOWN |
| ACK models | none in the rebuild; original UNKNOWN |
| Reconnection grace period | **not implemented** — a dropped client is treated as gone immediately |
| Retry / backoff | client `enableReconnection()`; server has no replay buffer |
| Sequence gap recovery | `seq` is emitted but the client never detects a gap |
