## 5. Decorations architecture

Three layers, mirroring the room vertical's repo/service/routes split:
- **`decoration.prisma-repo.ts`** — owns the two DB transactions (buy, equip) + catalog/inventory reads. `DecorationKind` (0/1/2) and `KIND_PROFILE_COL` map each kind to its Profile cache column (`avatarFrameUrl` / `entryEffectUrl` / `bubbleUrl`).
- **`decoration.service.ts`** — thin orchestration: wraps buy in `withIdempotency` (T1.2), shapes snake_case client payloads. Self-only inventory (keyed by the passed user id).
- **`decoration.routes.ts`** — REST surface; buy carries the money rate-limit + reads the `Idempotency-Key` header.

## 6. API endpoints

| Endpoint | Method | Auth | Body/Headers | Purpose |
|---|---|---|---|---|
| `/decorations` | GET | public | — | Enabled catalog (kind/sort ordered) |
| `/decorations/me` | GET | user (self-only) | — | Caller's inventory (item + equipped + expiry) |
| `/decorations/:id/buy` | POST | user | `Idempotency-Key?` | Buy (debit coins → ledger → inventory row, one tx) |
| `/decorations/:id/equip` | POST | user | — | Equip (atomic dual-write) |

Inventory is self-only **by construction** — addressed via `req.user.id`, with no user-id path parameter to reach another user's bag.

## 7. Buy flow (single transaction + idempotency)

```
POST /decorations/:id/buy  (Idempotency-Key?)
  → withIdempotency(scope=decoration:buy:{userId}, key)      [T1.2 — replay returns cached result]
      → prisma.$transaction:
          load item (enabled?)                → 404 decoration_not_found
          owned & not expired?                → 409 already_owned
          wallet.coins >= priceCoins?         → 400 insufficient_coins
          tx.wallet.update(coins -= price)
          tx.walletLedger.create(delta=-price, balanceAfter, reason=DecorationBuy, refType='decoration', refId=item)
          tx.userDecoration.create/update(expiresAt = durationDays ? now+N days : null)
      → { item_id, decoration_id, coins_after, expires_at }
```
All money/inventory writes are one `$transaction` → **fail = no debit, no ledger row, no inventory row** (tested). Idempotency ensures a retry with the same key returns the first result without re-charging (and without a spurious `already_owned`).

## 8. Equip flow (atomic dual-write)

```
POST /decorations/:id/equip           (on) / DELETE (off)
  → prisma.$transaction:
      owned? not expired?              → 404 decoration_not_owned / 409 decoration_expired
      col = KIND_PROFILE_COL[item.kind]
      on:  updateMany(demote other equipped of SAME kind) → update(this.equipped=true) → profile.update({[col]: item.url})
      off: update(this.equipped=false) → profile.update({[col]: null})
```
Both writes commit together or not at all — verified by a rollback test (Profile removed mid-tx → the `equipped` flag rolls back too). **One-equipped-per-kind** is enforced by the same-kind demote step.
